## 1. Executive Summary

dIKta.me V2 has **zero localization infrastructure**. All user-facing strings are hardcoded in English across 27 XAML files, 13 C# ViewModels/code-behind files, 3 converters, and ~60 strings in DiktaMe.Core.

| Metric | Count |
|--------|-------|
| Unique resource keys | ~540 |
| String instances to extract | ~710 |
| XAML files with strings | 27 |
| C# files with UI strings | 13 + 3 converters |
| Core library strings | ~60 |

**Scope:**
- **Languages:** English (en) as primary, Spanish (es-MX) as first translation. Scaffolded for future languages.
- **Coverage:** ALL windows from day 1 — Control Panel, Loading, Quick Chat, Wizard, Settings, Tray. Unlike V1 which only translated Settings.
- **Translation workflow:** Spanish layer AI-generated, then human-reviewed by developer for QA.

**What will NOT be translated:** LLM system prompts (`PromptDefaults.cs`), log messages (~252 instances), internal constants, API provider identifiers, model names, URLs.

## 2. Architecture

### 2.1 DiktaMe.App — WinUI 3 Resource System (.resw)

WinUI 3 unpackaged apps use `Microsoft.Windows.ApplicationModel.Resources.ResourceLoader` with `.resw` files organized by language folder.

**XAML localization** uses the `x:Uid` directive:

```xml
<!-- Before -->
<TextBlock Text="General" FontSize="24" FontWeight="SemiBold"/>

<!-- After -->
<TextBlock x:Uid="Settings_General_Title" FontSize="24" FontWeight="SemiBold"/>
```

The `.resw` entry: `Settings_General_Title.Text` = `"General"`

**C# localization** uses a `LocalizationService` singleton wrapping `ResourceLoader`:

```csharp
public sealed class LocalizationService
{
    private readonly ResourceLoader _loader = new();

    public string GetString(string key) => _loader.GetString(key);

    public string GetFormatted(string key, params object[] args)
        => string.Format(CultureInfo.CurrentCulture, _loader.GetString(key), args);
}
```

### 2.2 DiktaMe.Core — Standard .NET Resources (.resx)

DiktaMe.Core is a plain class library — it cannot use WinUI's `ResourceLoader`. Uses standard `.resx` with `ResXFileCodeGenerator` for strongly-typed access:

```csharp
// Auto-generated from CoreStrings.resx
throw new InvalidOperationException(CoreStrings.GeminiApiKeyNotConfigured);
```

`ResourceManager` respects `CultureInfo.CurrentUICulture` and falls back to neutral culture (English) automatically.

### 2.3 Language Switching — App Restart Required

WinUI 3's `ResourceLoader` reads resources at startup. There is no clean way to reload all `x:Uid`-resolved strings at runtime without recreating every window.

**Decision: Language change requires app restart.** Matches V1 behavior and is the standard WinUI 3 pattern.

Implementation:
1. User selects language in Settings > General
2. Persisted to `AppSettings.General.UiLanguage` (new property, separate from `Language` which controls transcription)
3. On next startup, `App.xaml.cs` calls `ApplicationLanguages.PrimaryLanguageOverride = savedUiLanguage` before any UI
4. InfoBar in GeneralSettingsPage: "Restart required for language change to take effect"

### 2.4 UI Language vs. Transcription Language

These are independent settings:
- **`UiLanguage`** — controls interface localization (requires restart)
- **`Language`** — controls STT transcription language parameter (no restart needed)

A user may want the UI in Spanish but transcribe English speech, or vice versa.

## 3. Resource File Structure

```
src/DiktaMe.App/
  Strings/
    en/
      Resources.resw          ← Primary (all ~480 App strings)
    es-MX/
      Resources.resw          ← Spanish translation

src/DiktaMe.Core/
  Resources/
    CoreStrings.resx           ← Primary (English, ~60 strings)
    CoreStrings.es-MX.resx     ← Spanish translation
    CoreStrings.Designer.cs    ← Auto-generated by ResXFileCodeGenerator
```

**Adding a new language later = adding one new `.resw` folder + one new `.resx` file.** No code changes required — the resource system handles fallback automatically.

### Project Configuration

**DiktaMe.App.csproj** — add:
```xml
<PropertyGroup>
  <DefaultLanguage>en</DefaultLanguage>
</PropertyGroup>
```

**DiktaMe.Core.csproj** — add:
```xml
<ItemGroup>
  <EmbeddedResource Include="Resources\CoreStrings.resx"
                    Generator="ResXFileCodeGenerator"
                    LastGenOutput="CoreStrings.Designer.cs" />
</ItemGroup>
```

## 4. Key Naming Convention

### Pattern: `{Area}_{ElementGroup}_{Detail}`

Keys use underscores, are flat (not nested), grep-friendly, and sort well in `.resw` editors.

**XAML keys** get a `.Property` suffix for the target property:

| Key | Value | Source |
|-----|-------|--------|
| `Settings_General_Title.Text` | General | GeneralSettingsPage.xaml |
| `Settings_General_Language_Label.Text` | Language | GeneralSettingsPage.xaml |
| `Settings_Hotkeys_Dictate_Label.Text` | Dictate | HotkeysSettingsPage.xaml |
| `Settings_Hotkeys_InfoBar.Message` | Click Record, then press... | HotkeysSettingsPage.xaml |
| `Nav_General.Content` | General | SettingsWindow.xaml |
| `Wizard_Welcome_Title.Text` | Welcome to dIKta.me | WizardWelcomePage.xaml |

**C# keys** have NO property suffix:

| Key | Value | Source |
|-----|-------|--------|
| `ControlPanel_Status_Ready` | READY | ControlPanelViewModel.cs |
| `Loading_Status_Settings` | Loading settings... | LoadingViewModel.cs |
| `Notification_Error_RecordingFailed` | Recording failed | LoadingViewModel.cs |
| `Tray_Tooltip_Idle` | Idle | TrayIconViewModel.cs |
| `Common_Save` | Save | Shared across pages |

### Rules
1. Area prefix matches window/page: `Settings_General_`, `ControlPanel_`, `Wizard_`, `Loading_`, `QuickChat_`, `Tray_`
2. `Common_` prefix for shared labels: `Common_Save`, `Common_Cancel`, `Common_Delete`, `Common_Refresh`
3. No abbreviations in keys (`Description` not `Desc`)
4. Provider names (`OpenAI`, `Deepgram`, `Gemini`) are NOT translated — they're proper nouns
5. Brand name `dIKta.me` is NEVER translated

## 5. XAML Migration Strategy

### 5.1 Simple Text Properties

```xml
<!-- Before -->
<TextBlock Text="General" FontSize="24"/>

<!-- After -->
<TextBlock x:Uid="Settings_General_Title" FontSize="24"/>
```

`.resw`: `Settings_General_Title.Text` = `General`

### 5.2 Multiple Properties on One Element

`x:Uid` can set multiple properties simultaneously via separate `.resw` entries:

```xml
<TextBox x:Uid="Settings_Hotkeys_RecordInput" IsReadOnly="True"/>
```

`.resw`: `Settings_Hotkeys_RecordInput.PlaceholderText` = `Click Record to set hotkey`

### 5.3 InfoBar

```xml
<InfoBar x:Uid="Settings_Hotkeys_InfoBar" Severity="Informational" IsOpen="True"/>
```

`.resw`: `Settings_Hotkeys_InfoBar.Message` = `Click Record, then press your desired key combination.`

### 5.4 NavigationView Items

```xml
<muxc:NavigationViewItem x:Uid="Nav_General" Tag="general"/>
```

`.resw`: `Nav_General.Content` = `General`

### 5.5 ToolTips

For `ToolTipService.ToolTip` (especially on ControlPanel), use code-behind rather than the verbose `x:Uid` attached property syntax:

```csharp
ToolTipService.SetToolTip(reqPanel, _loc.GetString("ControlPanel_Stats_Req_Tooltip"));
```

### 5.6 Elements NOT Localized in XAML

- Brand names: `"dIKta.me"`, `"dIKta.me V2.0"`
- Glyph codes: `&#xE713;`
- Provider names as labels: `"OpenAI"`, `"Deepgram"`, `"Gemini"`
- API key format hints: `"sk-..."`, `"AIza..."`
- Model identifiers: `"nova-3"`, `"gemini-2.5-flash"`

## 6. C# Migration Strategy

### 6.1 ViewModel String Arrays (ComboBox Options)

```csharp
// Before
public string[] Languages { get; } = ["English", "Spanish"];

// After
public string[] Languages => [
    _loc.GetString("Settings_General_Lang_English"),
    _loc.GetString("Settings_General_Lang_Spanish"),
];
```

**Files affected:** GeneralSettingsViewModel, AIEngineSettingsViewModel, ModesSettingsViewModel, AudioSettingsViewModel

### 6.2 Status Text and Toggle Labels

```csharp
// Before
StatusText = "READY";

// After
StatusText = _loc.GetString("ControlPanel_Status_Ready");
```

### 6.3 Toast Notifications

```csharp
// Before
_notifications.ShowToast("Error", "Recording failed", ...);

// After
_notifications.ShowToast(
    _loc.GetString("Notification_Error_Title"),
    _loc.GetString("Notification_Error_RecordingFailed"), ...);
```

### 6.4 Formatted Strings

```csharp
// Before
UsageText = $"{WordsUsed:N0} / {WordsQuota:N0} words";

// After
UsageText = _loc.GetFormatted("Settings_Account_UsageText", WordsUsed, WordsQuota);
```

`.resw` en: `Settings_Account_UsageText` = `{0:N0} / {1:N0} words`
`.resw` es-MX: `Settings_Account_UsageText` = `{0:N0} / {1:N0} palabras`

`CultureInfo.CurrentCulture` handles number formatting automatically (15,000 in en → 15.000 in es-MX via `:N0`).

### 6.5 Converters

- **PipelineStateToTextConverter** → move display logic to ViewModel (already duplicated in ControlPanelViewModel)
- **PrivacyLevelToStringConverter**, **RefineModeToStringConverter** → use `new ResourceLoader()` directly in `Convert()`

### 6.6 DiktaMe.Core Exception Messages

```csharp
// Before
throw new InvalidOperationException("Gemini API key not configured.");

// After
throw new InvalidOperationException(CoreStrings.GeminiApiKeyNotConfigured);
```

Strongly-typed `CoreStrings` class auto-generated from `CoreStrings.resx`.

## 8. Spanish Translation Workflow

### Step 1: Extract English Strings
Create all `.resw` and `.resx` files with English values. This is the source of truth.

### Step 2: AI Translation
Use an LLM to translate all English values to Mexican Spanish (es-MX).

**Translation prompt rules:**
1. Preserve all `{0}`, `{1}`, `:N0` format placeholders exactly
2. Do NOT translate: brand names (`dIKta.me`, `OpenAI`, `Deepgram`, `Ollama`, `Anthropic`, `Gemini`, `Whisper`, `Claude`, `GPT`), technical acronyms (`API`, `LLM`, `STT`, `DPAPI`, `PII`, `VRAM`, `GPU`, `URL`), keyboard shortcuts, file extensions
3. Use formal-casual Mexican Spanish (usted implied but not heavy)
4. Keep the same key names, only translate values
5. Standard UI verb mapping: Save=Guardar, Cancel=Cancelar, Delete=Eliminar, Reset=Restablecer, Browse=Examinar, Refresh=Actualizar

### Step 3: Human QA Review
Developer reviews for:
- Technical accuracy (does the description match the feature?)
- String length (Spanish is ~30% longer; see Section 9.2)
- Consistent terminology across all pages
- Format specifier preservation (no broken `{0}`)
- Gender/number agreement in context

### Step 4: Validation Build
Build, switch to es-MX, walk every screen checking:
- No truncated text (buttons, ComboBox, nav items)
- No raw key names displayed (missing translations)
- Format strings render correctly with data
- Tooltips display correctly

### Step 5: V1 Reference
Consult V1 Spanish translations at `E:\git\diktate\src\locales\es\{common.json,settings.json}` for consistent terminology where features overlap.

## 9. Testing Strategy

### 9.1 Missing Key Detection (xUnit)

```csharp
[Fact]
public void AllEnglishKeysHaveSpanishTranslations()
{
    var enKeys = LoadResw("Strings/en/Resources.resw");
    var esKeys = LoadResw("Strings/es-MX/Resources.resw");
    var missing = enKeys.Except(esKeys);
    Assert.Empty(missing);
}

[Fact]
public void AllXamlUidReferencesExistInResources()
{
    var uids = ScanXamlForUids("Views/**/*.xaml");
    var keys = LoadResw("Strings/en/Resources.resw");
    var missing = uids.Where(uid => !keys.Any(k => k.StartsWith(uid + ".")));
    Assert.Empty(missing);
}
```

### 9.2 Layout Overflow Awareness

Spanish text is 20-35% longer than English. Critical areas:

| UI Element | English | Risk |
|------------|---------|------|
| NavigationViewItem Content | "Dictation Presets" (18 chars) | Medium — `OpenPaneLength="180"` |
| Button Content | "Reset to Defaults" (18 chars) | Medium |
| ControlPanel toggle labels | "SOUND: ON" (9 chars) | Low |
| ControlPanel stat labels | "WORD/MIN" (8 chars) | Low |
| InfoBar messages | Long sentences | Low (wraps) |
| Toast notifications | Short sentences | Low (system wraps) |

**Mitigations:**
- `TextTrimming="CharacterEllipsis"` on constrained elements
- Increase `OpenPaneLength` if needed
- Use shorter Spanish alternatives where space is critical
- Test all buttons and nav items visually

### 9.3 CultureInfo Formatting

Verify number/date formatting uses `CultureInfo.CurrentCulture`:
- `{0:N0}` → `15,000` (en) vs `15.000` (es-MX)
- Duration displays, word counts, file sizes

## 12. Open Questions

### 12.1 Unpackaged App + .resw Loading

The app uses `WindowsPackageType=None` (unpackaged). Need to verify in Phase 1 that `ResourceLoader` finds `.resw` files in the output directory structure. Windows App SDK 1.6 should support this, but earlier versions had issues with unpackaged resource loading.

**Fallback if .resw doesn't work unpackaged:** Use `.resx` files for everything (both App and Core), with a custom `ResourceLoader` wrapper. This is less elegant but guaranteed to work.

### 12.2 Pluralization

WinUI 3's `.resw` format has no native plural support. For the rare cases (e.g., "1 day remaining" vs "5 days remaining"):

```csharp
StatusText = days == 1
    ? _loc.GetFormatted("Account_DayRemaining_One", days)
    : _loc.GetFormatted("Account_DayRemaining_Other", days);
```

Sufficient for English/Spanish. If many-plural-form languages (Arabic, Polish) are added later, consider a pluralization library.

### 12.3 RTL Future-Proofing

Not investing now. Both EN and es-MX are LTR. WinUI 3 handles `FlowDirection` automatically per language, but the Control Panel's custom layout would need a manual RTL audit. Defer until an RTL language is actually needed.

### 12.4 Trimmer Compatibility

`ResourceLoader` (Windows App SDK) and `ResourceManager` (.NET) should both be trim-safe in .NET 8. Verify during Phase 1 that a `PublishTrimmed=true` Release build loads resources correctly.

### 12.5 Resource File Tooling

`.resw` files are XML — editable in VS resource editor, or in any text editor. For bulk operations (AI translation, key auditing), consider a script that reads/writes `.resw` XML programmatically. The format is identical to `.resx` (just different extension for WinUI).

## Appendix A: LocalizationService

```csharp
// src/DiktaMe.App/Services/LocalizationService.cs
using Microsoft.Windows.ApplicationModel.Resources;
using System.Globalization;

namespace DiktaMe.App.Services;

/// <summary>
/// Centralized service for loading localized strings from .resw resources.
/// Registered as singleton in DI. All ViewModels and code-behind use this
/// instead of creating ResourceLoader instances directly.
/// </summary>
public sealed class LocalizationService
{
    private readonly ResourceLoader _loader;

    public LocalizationService()
    {
        _loader = new ResourceLoader();
    }

    /// <summary>Gets a localized string by key name (without .Property suffix).</summary>
    public string GetString(string key) => _loader.GetString(key);

    /// <summary>Gets a localized format string and fills in arguments using CurrentCulture.</summary>
    public string GetFormatted(string key, params object[] args)
        => string.Format(CultureInfo.CurrentCulture, _loader.GetString(key), args);
}
```
